# About

A static Astro 7 portal for developer notes. Start with a section or topic, then follow the connections between entries.

## Run locally

Use Node 26.x and npm 11.10 or newer. Check `node --version` and `npm --version` before installing.

```sh
npm ci
npm run dev
```

Development runs at <http://localhost:4321> and includes drafts. For production routing and headers:

```sh
npm run build
npm run preview
```

The local Wrangler server runs at <http://localhost:8788>. `preview` serves local assets; it does not publish a Worker Preview. Search works against the Pagefind index generated by the build. Rebuild after editing content to update search.

After changing section keys in `src/site.ts`, stop and restart `npm run dev`. Astro loads the content schema separately and can retain old section types during a rename. A production build does not refresh an already running development server.

## Content and structure

The five sections are Notes, Experiments, Concepts, Miscellaneous, and Vault. Section definitions live in `src/site.ts`. Entries keep their `/<slug>/` URL when their section changes. Topics span sections; topic pages group entries by growth stage. Recent lists use the last significant revision date. RSS announces new entries using the original publication date.

Write plain Markdown in `src/content/portal/<slug>/index.md`, with local images beside it. See [the authoring rules](src/content/AGENTS.md) for frontmatter and conventions. The five published starter entries are explicitly labelled examples; one draft demonstrates preview filtering. All start at the required `abstract` stage. Replace this content before publishing. The Vault example uses Big Buck Bunny solely to demonstrate click-to-load video.

`src/layouts/BaseLayout.astro` supplies the document shell. Reusable portal components handle badges, metadata, entry lists, connections, and pagination. `src/lib/portal.ts` owns the draft filter, stable entry URLs, ordering, backlinks, and related-entry ranking. Search alone loads Pagefind's Component UI. Themes follow the operating system unless the reader chooses a preference.

The visual design uses warm neutral surfaces, a restrained accent, system sans-serif headings, and Charter-class serif reading text. `src/styles/global.css` imports layered tokens and shared foundations; component and page styles live beside their Astro owners. See [CSS architecture](docs/css-architecture.md) for the methodology comparison, naming conventions, file ownership, and vendor adapters. Responsive grids, reduced-motion support, and visible keyboard focus work in both themes.

The implementation follows [the architecture](docs/architecture.md). It uses exactly the 14 selected direct packages, with no adapters, application server, Markdown plugins, CSS framework, analytics, or external fonts. An npm override aligns axe's transitive `playwright-core` with the pinned Playwright runner; it adds no direct package. Install scripts remain disabled and the seven-day release-age policy stays enabled.

## Verify

```sh
npx playwright install chromium
npm run check
npm run test:content
npm run build
npm run test:html
npm run test:links
npm run test:e2e
npm run test:perf
```

CI runs these checks plus lychee. Content tests build isolated temporary fixtures; they never edit working entries. They cover invalid schemas, reserved/retired slugs, empty sections, pagination, backlinks, optimized images, production draft exclusion, and preview `noindex`. Browser tests cover both themes, WCAG 2.2 AA axe rules, keyboard controls, narrow screens, reduced motion, privacy before video activation, CSP, host headers, permanent URLs, search filters, and copy/video behavior.

`npm run test:e2e` builds and serves a temporary copy of the site with the current content plus dedicated feature fixtures. It checks the published entries and exercises optional features independently of starter content. The temporary copy is removed afterward; the working content and production `dist/` are unchanged. Stop any server on port 8788 before running it so the suite can start its isolated Wrangler server.

The entry JavaScript budget counts executable scripts; JSON-LD is structured data. The combined theme, copy, and video scripts stay below 1.5 KB. Render-blocking CSS is measured after gzip. Lighthouse enforces a minimum score of 0.95 in all four categories on the home page and an entry. Field Core Web Vitals and manual screen-reader/release checks remain separate from laboratory results.

## Before publishing

Confirm the site URL. `https://bipinpaulbedi.com` remains the documented example in `astro.config.mjs`, `public/robots.txt`, and `wrangler.jsonc`. Replace `REPLACE_WITH_AUTHOR_NAME` and `https://github.com/example/blog` in `src/site.ts`. Enable GitHub Discussions in the confirmed repository and replace the starter entries.

Replace the Twitter (X) and LinkedIn placeholder URLs in `SOCIAL_PROFILES` in `src/site.ts`. The footer uses these URLs on every page.

Set the GitHub repository variable `SITE_URL` to the confirmed production URL. CI then checks that live sitemap URLs remain built or redirected, and the weekly job checks production headers. Without that variable, local link checks still run and live checks are skipped.

Configure Workers Builds and Cloudflare Access using architecture §9–10. Production excludes drafts. Branch builds use `SHOW_DRAFTS=true` and put `noindex` on every HTML page; verify Access protection before publishing drafts. No deployment was performed as part of implementation. Use the dashboard-managed workflow described in the architecture.
